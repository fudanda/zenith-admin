# CRUD Step 0：信息收集

仅在**从零开发 CRUD 模块**时读取。修改已有模块、异步任务、排错和发版场景不要加载本文件。

## 提问方式

- 在生成代码前补齐下方信息；用户已明确提供的内容不要重复询问
- 优先使用当前环境提供的结构化交互式提问能力，且一次只问一个问题；没有该能力时再用普通对话
- 收集完成后展示汇总，用户确认后进入 Step 1
- **快速模式**：用户明确说「简单的 XXX 管理，用默认配置」时，可将可选项按「不需要」处理；
  必填项仍须确认

## 必填项

| 信息项 | 说明 | 未提供时的处理 |
| --- | --- | --- |
| 模块中文名 | 如「部门管理」 | 询问中文名称 |
| 实体英文名 | 单数，如 Department / department | 询问英文名 |
| API 路径前缀 | 如 `/api/departments` | 由实体名推导后确认 |
| 数据库表名 | 如 `departments` | 由英文名复数推导后确认 |
| 权限前缀 | 如 `system:department` | 由模块名推导后确认 |
| 字段列表 | 字段名、类型、是否必填、是否唯一 | 询问字段与约束 |
| 父菜单 ID | 挂在哪个一级菜单下 | 先读 `packages/shared/src/seed/menus.ts` 与目标分片确认占用，再询问 |

## 可选项

不要默认开启，逐项确认：

| 选项 | 影响 | 判定依据 |
| --- | --- | --- |
| MSW Mock | 决定 Step 11 是否执行 | 需要 Demo 模式（`VITE_DEMO_MODE=true`）时才要 |
| 状态字段 | 复用现有 `statusEnum` 或新建枚举 | — |
| 关联实体 | 多对一 FK 或多对多联表 | — |
| 数据导出 | 后端注册导出实体定义 + 前端 `ExportButton` | — |
| 时间范围筛选 | 列表搜索栏添加时间范围 | — |
| 下拉源（`GET /all`） | 后端添加受相同行级权限约束的 `/all`，前端开启 `lookup` | 启用 MSW 时同步添加 Mock `/all` |
| 数据权限（dataScope） | 表加 `department_id` + 查询追加 scope 条件 | 业务数据通常需要；配置数据通常不需要；日志按需求判断 |
| 租户隔离 | 表加 `tenant_id` + `tenantCondition` | 业务数据通常需要；配置与平台级功能通常不需要；仅 `MULTI_TENANT_MODE=true` 时生效 |
| 表格批量操作 | 有界、可快速完成的选中行操作使用同步 `/batch` | 大数据量、长耗时、需进度 / 重试 / 取消时改用任务中心 |

dataScope、租户隔离的实现见 [backend-patterns.md](./backend-patterns.md)；
异步批量任务见 [async-tasks.md](./async-tasks.md)。
